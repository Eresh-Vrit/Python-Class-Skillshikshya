Class Variables
Data shared by every object in a class.

The Big Idea

So far, every object has had its own copy of each attribute. But sometimes you want a value that is shared across all objects of a class.

  • 📊Instance variables belong to one object (self.name).
  • 📊Class variables belong to the class itself (Student.class_year).
shared across all instances
accessed via ClassName.var
great for counters and defaults
4 / 24

Instance vs Class Variables ⚖️

Instance Variable

Defined inside __init__ using self. Each object gets its own copy.

class Student:
    def __init__(self, name):
        self.name = name  # instance

s1 = Student("Bob")
s2 = Student("Ann")
# s1.name and s2.name are different

Class Variable

Defined directly inside the class. Shared by every object.

class Student:
    class_year = 2024  # class

    def __init__(self, name):
        self.name = name

# All students share class_year
print(Student.class_year)  # 2024
📌 Use instance variables for unique data. Use class variables for data that should be the same for every object.

Class Variables in Action: Student class_year 🎓

class Student:
    class_year = 2024
    num_students = 0

    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age

student1 = Student("SpongeBob", 30)
student2 = Student("Patrick", 35)

print(student1.name)         # SpongeBob
print(Student.class_year)  # 2024

What is Happening?

  • 📊class_year is created once, at the class level.
  • 📊Both students share the same class_year.
  • 📊We access it through Student.class_year.
💡 You can also read class_year through an object (student1.class_year), but using the class name is clearer.

Counting Objects with Class Variables 🔢

class Student:
    class_year = 2024
    num_students = 0

    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age
        Student.num_students += 1

student1 = Student("SpongeBob", 30)
student2 = Student("Patrick", 35)

print(Student.num_students)  # 2

How the Counter Works

  • 🔢num_students starts at 0.
  • 🔢Every time __init__ runs, it adds 1.
  • 🔢The total lives in the class, not in any one student.
✅ Class variables are perfect for counters, shared settings, and default values.

Inheritance
Build new classes from existing ones.

The Big Idea

Inheritance lets a new class reuse the attributes and methods of an existing class. The child class gets everything from the parent, and can add its own features.

class Dog(Animal):
    pass  # Dog inherits everything from Animal
parent = base class
child = derived class
IS-A relationship

Inheritance Basics: Animal → Dog/Cat/Mouse 🐾

class Animal:
    def __init__(self, name: str):
        self.name = name
        self.is_alive = True

    def eat(self):
        print(f"{self.name} is eating")

    def sleep(self):
        print(f"{self.name} is sleeping")

class Dog(Animal):
    pass

class Cat(Animal):
    pass

class Mouse(Animal):
    pass

The Parent Class

  • 🐾Animal stores shared data and behavior.
  • 🐾Dog, Cat, and Mouse all inherit from Animal.
  • 🐾No code is duplicated in the children.
💡 If a class has no new code, use pass to tell Python "this class exists but has nothing extra yet."

Multiple Inheritance 🐇🦅🐟

class Animal:
    def __init__(self, name: str):
        self.name = name

    def eat(self):
        print(f"{self.name} is eating")

    def sleep(self):
        print(f"{self.name} is sleeping")

class Prey(Animal):
    def flee(self):
        print(f"{self.name} is fleeing")

class Predator(Animal):
    def hunt(self):
        print(f"{self.name} is hunting")
class Rabbit(Prey):
    pass

class Hawk(Predator):
    pass

class Fish(Prey, Predator):
    pass

fish = Fish("Nemo")
fish.eat()   # Nemo is eating
fish.flee()  # Nemo is fleeing
fish.hunt()  # Nemo is hunting
📌 Fish inherits from both Prey and Predator, so it can both flee and hunt.

Abstract Classes
Blueprints that cannot be built directly.

The Big Idea

An abstract class is a template. You cannot create objects from it directly. It forces every child class to implement certain methods.

from abc import ABC, abstractmethod

class Vehicle(ABC):
    @abstractmethod
    def go(self): pass
ABC = Abstract Base Class
@abstractmethod = required
cannot instantiate directly

Abstract Classes with ABC: Vehicle 🚗🏍️🚤

from abc import ABC, abstractmethod

class Vehicle(ABC):
    @abstractmethod
    def go(self):
        pass

    @abstractmethod
    def stop(self):
        pass

class Car(Vehicle):
    def go(self):
        print("You drive the car")

    def stop(self):
        print("You stop the car")
class Motorcycle(Vehicle):
    def go(self):
        print("You ride the motorcycle")

    def stop(self):
        print("You stop the motorcycle")

class Boat(Vehicle):
    def go(self):
        print("You sail the boat")

    def stop(self):
        print("You anchor the boat")

# vehicle = Vehicle()  # TypeError!
⚠️ Creating an object from Vehicle directly raises a TypeError. You must create a concrete child like Car, Motorcycle, or Boat.

⬆️
super()
Call the parent class from a child.

The Big Idea

When a child overrides __init__ or another method, it can still call the parent's version using super(). This avoids duplicating parent logic.

class Circle(Shape):
    def __init__(self, color, is_filled, radius):
        super().__init__(color, is_filled)  # call Shape's __init__
        self.radius = radius
super() = parent class
reuse parent code
17 / 24

super() in __init__ 🟠🟦🔺

class Shape:
    def __init__(self, color: str, is_filled: bool):
        self.color = color
        self.is_filled = is_filled

class Circle(Shape):
    def __init__(self, color, is_filled, radius):
        super().__init__(color, is_filled)
        self.radius = radius

class Square(Shape):
    def __init__(self, color, is_filled, width):
        super().__init__(color, is_filled)
        self.width = width

Reusing the Parent Constructor

  • ⬆️Shape sets color and is_filled.
  • ⬆️Circle and Square call super().__init__() first.
  • ⬆️Then they add their own attributes.
⚠️ If you override __init__ and forget super().__init__(), the parent attributes may not be created.

super() in Methods: Extending describe() 📝

class Shape:
    def __init__(self, color, is_filled):
        self.color = color
        self.is_filled = is_filled

    def describe(self):
        print(f"It is {self.color} and "
              f"{'filled' if self.is_filled else 'not filled'}")

class Circle(Shape):
    def __init__(self, color, is_filled, radius):
        super().__init__(color, is_filled)
        self.radius = radius

    def describe(self):
        print(f"It is a circle with area "
              f"{3.14 * self.radius ** 2} cm^2")
        super().describe()

Overriding and Extending

  • 📝Circle has its own describe() method.
  • 📝It prints the circle-specific info first.
  • 📝Then it calls super().describe() to also print the shared info.
💡 Use super() when you want to add behavior, not completely replace it.

Polymorphism
Many shapes, one method name.

The Big Idea

Polymorphism means "many forms." Different classes can implement the same method name in different ways. You can then treat them all the same.

for shape in shapes:
    print(f"{shape.area()} cm^2")  # works for any shape!
same interface
different behavior
loop-friendly
20 / 24

Polymorphism with Shapes 🟠🟦🔺

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius ** 2

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2
class Triangle(Shape):
    def __init__(self, base, height):
        self.base = base
        self.height = height

    def area(self):
        return self.base * self.height * 0.5

shapes = [Circle(4), Square(5), Triangle(6, 7)]

for shape in shapes:
    print(f"{shape.area()} cm^2")

# 50.24 cm^2
# 25 cm^2
# 21.0 cm^2
🎭 Every shape calculates area differently, but we call area() the same way in the loop.

Adding Pizza to the Shapes List 🍕

class Pizza(Circle):
    def __init__(self, topping: str, radius: float):
        super().__init__(radius)
        self.topping = topping

shapes = [
    Circle(4),
    Square(5),
    Triangle(6, 7),
    Pizza("pepperoni", 15)
]

for shape in shapes:
    print(f"{shape.area()} cm^2")

Why This Works

  • 🍕Pizza inherits from Circle, so it already has area().
  • 🍕We add a topping attribute.
  • 🍕The loop still works because every object has area().
✅ Polymorphism makes your code flexible. Add new shapes without changing the loop.

Common Mistakes - Don't Fall For These! ⚠️

❌ Forgetting super() in child __init__
class Circle(Shape):
  def __init__(self, color, radius):
    self.radius = radius ← color never set!
# Fix: call super().__init__(color, is_filled) first
❌ Instantiating an abstract class
v = Vehicle() ← TypeError! ❌
c = Car() ← correct ✅
❌ Skipping an abstract method
class BadCar(Vehicle):
  def go(self): ... ← ok
  # forgot stop() → TypeError on creation!
❌ Confusing class variable with instance variable
s1.class_year = 2025 ← creates an instance copy!
Use Student.class_year = 2025 to change the shared value.
❌ Forgetting pass for empty child classes
class Rabbit(Prey):
  # body cannot be truly empty
class Rabbit(Prey): pass ← correct
❌ Indentation errors inside classes
All methods must be indented under the class.
All method bodies must be indented under def.
