What is an Object? 🏠

An object is a bundle of related attributes (data) and methods (actions). Look around you — almost everything is an object.

📱

Phone

  • •version: int
  • •is_on: bool
  • •price: float
☕

Cup

  • •liquid: str
  • •temperature: int
  • •is_empty: bool
📚

Book

  • •title: str
  • •pages: int
💡 Each object groups what it knows (attributes) and what it can do (methods) into one tidy package.

Attributes — What an Object HAS 📦

Attributes are like variables that belong to an object. They describe the object's current state.

# Phone attributes
version = 16
is_on   = True
price   = 999.99

# Cup attributes
liquid      = "coffee"
temperature = 65
is_empty    = False

# Book attributes
title = "Python Crash Course"
pages = 320

Attributes = variables attached to an object

They answer the question: "What does this object have?"

Different objects, different values

One phone can be on; another can be off. One cup can be empty; another can be full.

✅ Attributes store the state of an object.

From Object to Class 📐

A class is a blueprint used to design the structure and layout of an object. It defines what attributes and methods every object will have.

Class The blueprint (the recipe)
Object One real thing built from the blueprint
  • •A class describes what an object should look like
  • •One class can create many objects
  • •Each object is independent
# Class = blueprint for a Car
class Car:
    pass

# Objects = real cars built from the blueprint
car1 = Car()
car2 = Car()
car3 = Car()

print(car1 == car2)
# False -> three independent objects
💡 Car is the blueprint. car1, car2, and car3 are real cars built from it.

Creating a Class 🏗️

Rules for writing classes:

  • •Start with the class keyword
  • •Use PascalCase for the class name
  • •The body is indented
  • •pass means "empty on purpose"
❌ class car:   ❌ class bank_account:
✅ class Car:   ✅ class BankAccount:

# Car is now a blueprint we can use

print(type(my_car))

__init__
The constructor sets up every object safely.

The Constructor

__init__ is a special method that Python calls automatically when you create a new object. It sets up the object's attributes.

class Car:
    def __init__(self, model, year, color, for_sale):
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

car1 = Car("Mustang", 2024, "red", False)
print(car1.model)  # Mustang
__init__ runs automatically
self stores data on the object
no more missing attributes

Creating Objects 🚗

Use the class name like a function. Pass the values __init__ expects.

class Car:
    def __init__(self, model, year,
                 color, for_sale):
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

car1 = Car("Mustang", 2024, "red", False)
car2 = Car("Corvette", 2025, "blue", True)
car3 = Car("Charger", 2026, "black", False)
car1 Mustang, 2024, red, not for sale
car2 Corvette, 2025, blue, for sale
car3 Charger, 2026, black, not for sale
✅ One class, three independent cars — each with its own data.

Accessing Attributes 🔍

Use the dot operator to read an object's attributes.

car1 = Car("Mustang", 2024, "red", False)

# Read attributes with dot notation
print(car1.model)
# Mustang

print(car1.year)
# 2024

print(car1.color)
# red

print(car1.for_sale)
# False

Dot operator

object.attribute looks inside the object and finds the value.

Attributes can be changed

car1.color = "blue" updates that specific car only.

✅ Each object stores its own attribute values.

Type Annotations 🏷️

Type hints tell humans (and tools) what kind of value each attribute and argument should be. They do not change how the code runs.

class Car:
    def __init__(self, model: str,
                 year: int,
                 color: str,
                 for_sale: bool) -> None:
        self.model:    str  = model
        self.year:     int  = year
        self.color:    str  = color
        self.for_sale: bool = for_sale

Common type hints

  • •str for text
  • •int for whole numbers
  • •float for decimals
  • •bool for True/False
📌 -> None means "this method does not return a value."

Understanding self 🙋

self is always the first parameter of every method. It refers to this object we are creating right now.

class Car:
    def __init__(self, model, year,
                 color, for_sale):
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

car1 = Car("Mustang", 2024, "red", False)
car2 = Car("Corvette", 2025, "blue", True)

Think of self as "this object"

self.model = model means "Give this object the model that was passed in."

💡 Python passes self automatically. You do not write it when creating the object.
❌ model = model creates a local variable, not an attribute. Always use self.model.

Many Objects from One Class 🚗🚙🚕

The same blueprint can create unlimited objects. Each object is independent and stores its own data.

class Car:
    def __init__(self, model: str,
                 year: int, color: str,
                 for_sale: bool) -> None:
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

car1 = Car("Mustang", 2024, "red", False)
car2 = Car("Corvette", 2025, "blue", True)
car3 = Car("Charger", 2026, "black", False)

print(car1.model)  # Mustang
print(car2.model)  # Corvette
print(car3.model)  # Charger
car1 owns "Mustang"
car2 owns "Corvette"
car3 owns "Charger"
✅ Changing car1.color does not change car2.color.

Methods
Functions that belong to objects.

Methods in Action

A method is a function defined inside a class. The first parameter is always self, and you call it with dot notation.

class Car:
    # ... __init__ here ...

    def drive(self) -> None:
        print(f"You drive the {self.color} {self.model}")

    def stop(self) -> None:
        print(f"You stop the {self.color} {self.model}")

car1 = Car("Mustang", 2024, "red", False)
car1.drive()  # You drive the red Mustang
car1.stop()   # You stop the red Mustang
method = function in a class
first parameter is self
call with object.method()

Methods with More Detail 🎬

A method can use all of an object's attributes at once. The describe() method prints the full picture.

class Car:
    def __init__(self, model: str,
                 year: int, color: str,
                 for_sale: bool) -> None:
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

    def drive(self) -> None:
        print(f"You drive the {self.color} {self.model}")

    def stop(self) -> None:
        print(f"You stop the {self.color} {self.model}")

    def describe(self) -> None:
        print(f"{self.year} {self.color} {self.model}")
car1 = Car("Mustang", 2024, "red", False)
car2 = Car("Corvette", 2025, "blue", True)

car1.drive()
car1.stop()
car1.describe()

car2.describe()
✅ Each method uses self to read the attributes of the car that called it.
💡 self is always first. It lets the method say "my model" and "my color".

Organizing Code in Separate Files 📁

Classes can be placed in their own Python files and imported wherever they are needed. This keeps projects clean and reusable.

car.py
class Car:
    def __init__(self, model: str,
                 year: int, color: str,
                 for_sale: bool) -> None:
        self.model    = model
        self.year     = year
        self.color    = color
        self.for_sale = for_sale

    def drive(self) -> None:
        print(f"You drive the {self.color} {self.model}")
main.py
from car import Car

car1 = Car("Mustang", 2024, "red", False)

car1.drive()
💡 Put the class in car.py, then import it with from car import Car.
✅ Separate files make your code easier to read, reuse, and maintain.

Common Mistakes — Don't Fall For These! ⚠️

❌ Forgetting self in a method
def drive(): ...   # TypeError!
def drive(self): ... # correct
❌ Using model instead of self.model
self.model = model   # stores on object
model = model         # local var, gone!
❌ Typo in attribute name
car1.modle   # AttributeError!
car1.model   # correct
❌ Calling a method without ()
car1.drive   # gives the method object
car1.drive() # runs it!
❌ Lowercase class names
class car:         # not convention
class Car:         # PascalCase
❌ Confusing class and object
Car is the blueprint.
car1 = Car() is a real object.
