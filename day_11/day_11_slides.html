Exception
Handling
Handle errors instead of crashing.

The Big Idea

An exception is an error that happens while a program is running. Without handling, Python stops the entire program immediately. Exception handling lets you catch the error and decide what to do instead.

  • ⚠️Bad user input, missing files, and dividing by zero all cause exceptions.
  • ⚠️try/except lets your program recover and keep running.
errors happen at runtime
catch them with try/except
keep the program alive

What Happens Without try/except? 💥

age = int(input("Enter your age: "))
print(f"You are {age} years old.")

# If the user types "abc" instead of a number:
ValueError: invalid literal for int() with base 10: 'abc'
# The program stops here. Nothing after this line runs!

Why This Is a Problem

  • 💥One bad input crashes the entire program.
  • 💥Any code after the error never runs.
  • 💥The user sees a scary, confusing error message.
⚠️ Real programs must expect that users, files, and networks will not always behave perfectly.

try / except Basics 🛡️

try:
    age = int(input("Enter your age: "))
    print(f"You are {age} years old.")
except:
    print("That was not a valid number!")

# Typing "abc" now prints a friendly message
# instead of crashing the program.

How try/except Works

  • 1️⃣Python runs the code inside try first.
  • 2️⃣If an error happens, it immediately jumps to except.
  • 3️⃣If there is no error, the except block is skipped entirely.
✅ The program keeps running after the try/except block, no matter what happened inside it.

Catching Specific Exceptions 🎯

try:
    number = int(input("Enter a number: "))
    print(10 / number)
except ValueError:
    print("That is not a number!")
💡 ValueError is just one type of exception. Naming it means we only catch that specific problem.

Why Name the Exception?

  • 🎯except ValueError: only catches invalid conversions like int("abc").
  • 🎯A bare except: catches everything — even mistakes in your own code!
  • 🎯Being specific makes bugs easier to find.
⚠️ This example still has a problem: dividing by 0 raises a DIFFERENT exception that we are not catching yet. Next slide fixes that.
7 / 20

Multiple except Blocks 🔀

try:
    number = int(input("Enter a number: "))
    result = 10 / number
    print(result)
except ValueError:
    print("That is not a number!")
except ZeroDivisionError:
    print("You cannot divide by zero!")

How Python Picks a Block

  • 🔀Python checks each except in order, top to bottom.
  • 🔀Only the block matching the exception type runs.
  • 🔀Typing "abc" triggers ValueError; typing "0" triggers ZeroDivisionError.
📌 One try can be followed by as many except blocks as you need, one per error type.

Catching Several Exceptions in One Line 📦

fruits = {"apple": 3, "banana": 5}

try:
    print(fruits["cherry"])
except (KeyError, IndexError):
    print("That item does not exist!")

# cherry is not a key in fruits, so KeyError happens
# and this except block catches it.

Grouping Exception Types

  • 📦Wrap the types in parentheses, separated by commas.
  • 📦Use this when two different errors should be handled the same way.
  • 📦Saves you from repeating the same print statement twice.
💡 If the errors need different messages, use separate except blocks instead (like the previous slide).

Getting the Error Message with "as e" 🔎

try:
    number = int("abc")
except ValueError as e:
    print("Error occurred:", e)

# Error occurred: invalid literal for int()
# with base 10: 'abc'

Why Capture the Exception?

  • 🔎as e stores the exception object in a variable named e.
  • 🔎Printing e shows Python's own description of what went wrong.
  • 🔎Very useful while debugging — you see the real reason for the failure.
📌 "e" is just a variable name — you could call it anything, but "e" or "error" is the common convention.

The else Clause: Only Runs If Nothing Fails ✅

try:
    number = int(input("Enter a number: "))
except ValueError:
    print("That is not a number!")
else:
    print(f"Great, you entered {number}")

# else only runs when the try block succeeds
# with NO exception at all.

Why Not Just Put It in try?

  • ✅else keeps the "success path" separate from the risky code.
  • ✅It only runs when try finishes with no error.
  • ✅Makes it clear which lines are "the risky part" and which are "what happens next."
💡 else is optional — most simple programs just use try and except without it.
11 / 20

The finally Clause: Always Runs 🔁

try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero!")
finally:
    print("Done trying the division.")

# Cannot divide by zero!
# Done trying the division.

Success or Failure, It Still Runs

  • 🔁finally runs whether or not an exception happened.
  • 🔁Great for cleanup code, like closing a file or a connection.
  • 🔁Runs even if the except block itself does not catch the error.
📌 Think of finally as "no matter what happens above, always do this before moving on."

Putting It Together: try / except / else / finally 🧩

try:
    age = int(input("Enter your age: "))
except ValueError:
    print("That is not a valid number!")
else:
    print(f"Your age is {age}")
finally:
    print("Thanks for using the program!")
# If the user enters "25":
# Your age is 25
# Thanks for using the program!

# If the user enters "abc":
# That is not a valid number!
# Thanks for using the program!
🧩 try = risky code. except = handle failure. else = handle success. finally = always run.

Raising Your Own
Exceptions
Sometimes YOU decide something is an error.

The Big Idea

So far, Python raised exceptions for us. But sometimes your own code needs to say "this is not allowed" — for example, a negative age. The raise keyword lets you trigger an exception on purpose.

if age < 0:
    raise ValueError("Age cannot be negative")
raise ExceptionType("message")
stops the function immediately
14 / 20

The raise Statement 🚨

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

set_age(-5)
# ValueError: Age cannot be negative
# The program stops here — unless we catch it!

try:
    set_age(-5)
except ValueError as e:
    print("Invalid age:", e)

Using raise Inside Your Own Functions

  • 🚨raise stops the function immediately, just like a real Python error.
  • 🚨You choose the exception type and the message.
  • 🚨Whoever calls your function can catch it with try/except.
✅ raise lets your own functions enforce rules, the same way Python enforces its own.

Custom Exception Classes 🏷️

class NegativeAgeError(Exception):
    pass

def set_age(age):
    if age < 0:
        raise NegativeAgeError("Age cannot be negative")
    return age

Why Make Your Own Exception?

  • 🏷️A custom exception has a name that describes YOUR specific problem.
  • 🏷️It inherits from the built-in Exception class.
  • 🏷️pass means it needs no extra code — the name itself is the point.
💡 NegativeAgeError is much clearer than a generic ValueError when other people read your code.
16 / 20

Using a Custom Exception in Practice 🎬

class NegativeAgeError(Exception):
    pass

def set_age(age):
    if age < 0:
        raise NegativeAgeError("Age cannot be negative")
    return age

try:
    set_age(-5)
except NegativeAgeError as e:
    print("Invalid age:", e)

# Invalid age: Age cannot be negative

It Works Just Like a Built-in Exception

  • 🎬except NegativeAgeError catches only our custom error.
  • 🎬as e still lets us read the error message.
  • 🎬Other exceptions (like ValueError elsewhere) are left alone.
📌 Custom exceptions make large programs much easier to debug — the exception name tells you exactly what broke.

Mini Project: A Safe Input Loop 🔒

def get_positive_number():
    while True:
        try:
            value = int(input("Enter a positive number: "))
            if value <= 0:
                raise ValueError("Number must be positive")
        except ValueError as e:
            print(f"Invalid input: {e}")
        else:
            return value
number = get_positive_number()
print(f"You entered {number}")

# Enter a positive number: abc
# Invalid input: invalid literal for int()...
# Enter a positive number: -3
# Invalid input: Number must be positive
# Enter a positive number: 7
# You entered 7
🔒 The loop keeps asking until the input is valid — one raise, one except, both bad-input cases handled.

Common Mistakes - Don't Fall For These! ⚠️

❌ Using a bare except: for everything
try: ...
except: print("Something broke")
# Hides typos and real bugs too! Name the exception.
❌ Putting only the safe code inside try
try:
  x = int(input())
print(10 / x) ← still crashes if x is 0!
# Fix: put every risky line inside try.
❌ Forgetting raise needs an exception
raise "Age cannot be negative" ← TypeError!
raise ValueError("Age cannot be negative") ← correct
❌ Confusing else with "the rest of the code"
else only runs if try had NO exception at all.
Code after the whole try/except runs either way.
❌ Catching the wrong exception type
except ZeroDivisionError: ← won't catch a ValueError!
# Match the except type to the real error.
❌ Custom exception without inheriting Exception
class MyError: pass ← not a real exception!
class MyError(Exception): pass ← correct
