Encapsulation
Bundle data and protect it from misuse.

The Big Idea

Encapsulation means keeping an object's data bundled together with the methods that use it, and hiding the details other code should not touch directly.

  • 🔒Attributes can be marked public, protected, or private.
  • 🔒Methods control how outside code reads or changes that data.

Public, Protected, and Private Attributes 🚦

Public

name — no underscore. Anyone can read or change it freely.

self.name = name

Protected

_name — one underscore. A hint: "internal use only," but Python does not enforce it.

self._pin = pin

Private

__name — two underscores. Python renames it so it is hard to access by accident.

self.__balance = balance
📌 None of these truly "lock" the data in Python — they are increasingly strong signals of intent, not walls.
5 / 22

Double Underscore and Name Mangling 🧪

class BankAccount:
    def __init__(self, owner: str, balance: float):
        self.owner = owner          # public
        self._pin = "1234"       # protected
        self.__balance = balance  # private

account = BankAccount("Sandy", 100)

print(account.owner)     # Sandy - fine
print(account._pin)      # 1234 - allowed, but discouraged
print(account.__balance)  # AttributeError!

What Just Happened?

  • 🧪Python renames __balance to _BankAccount__balance behind the scenes.
  • 🧪account.__balance no longer exists under that exact name.
  • 🧪This is called name mangling.
print(account._BankAccount__balance)  # 100
💡 You could still reach it this way, but you should not. Use methods instead, which we cover next.

Get Private Property Value: A Getter Method 🔍

class Person:
    def __init__(self, name, age):
        self.name = name
        self.__age = age

    def get_age(self):
        return self.__age

p1 = Person("Tobias", 25)
print(p1.get_age())  # 25

Why Not Just Use p1.__age?

  • 🔍__age is private, so p1.__age raises an AttributeError outside the class.
  • 🔍get_age() is a normal method that safely returns the value.
  • 🔍Any code outside the class must go through get_age() to read it.
💡 This is called a "getter" method — its only job is to get (return) the value of a private attribute.
7 / 22

Set Private Property Value: A Setter Method ✍️

class Person:
    def __init__(self, name, age):
        self.name = name
        self.__age = age

    def get_age(self):
        return self.__age

    def set_age(self, age):
        if age > 0:
            self.__age = age
        else:
            print("Age must be positive")
p1 = Person("Tobias", 25)
print(p1.get_age())  # 25

p1.set_age(26)
print(p1.get_age())  # 26

p1.set_age(-5)
# Age must be positive
print(p1.get_age())  # still 26
✅ The setter checks the value first. An invalid age is rejected instead of being stored.

Putting It Together: A Safer BankAccount 🏦

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def set_balance(self, balance):
        if balance < 0:
            print("Balance cannot be negative!")
        else:
            self.__balance = balance
account = BankAccount("Sandy", 100)

print(account.get_balance())  # 100

account.set_balance(250)
print(account.get_balance())  # 250

account.set_balance(-50)
# Balance cannot be negative!
print(account.get_balance())  # still 250
🔒 The balance can never become invalid, no matter what the outside code tries to set it to.

Opening Files: open() and File Modes 🔑

file = open("notes.txt", "r")
content = file.read()
print(content)
file.close()  # must close it yourself!
⚠️ If you forget file.close(), the file may stay locked or changes may not be saved properly.

Common File Modes

  • 📖"r" — read only. File must already exist.
  • ✍️"w" — write. Creates the file, erases existing content.
  • ➕"a" — append. Adds to the end, keeps old content.
  • 🔁"r+" — read and write, without erasing.
💡 open(filename, mode) is the same idea for every mode — only the mode letter changes what happens.
11 / 22

The with Statement: Closing Files Automatically 🤝

Without with

file = open("notes.txt", "r")
content = file.read()
file.close()  # easy to forget!

If an error happens before close(), the file may never close.

With with

with open("notes.txt", "r") as file:
    content = file.read()
# file is automatically closed here

print(content)

Python closes the file for you, even if an error occurs inside the block.

✅ Always prefer the with statement. It is shorter and safer than calling open() and close() yourself.

Reading Files: read(), readline(), readlines() 📖

# notes.txt contains:
# Hello, SpongeBob!
# Welcome to Bikini Bottom.

with open("notes.txt", "r") as file:
    print(file.read())
# whole file as ONE string

with open("notes.txt", "r") as file:
    print(file.readline())
# just the FIRST line: "Hello, SpongeBob!"
with open("notes.txt", "r") as file:
    print(file.readlines())
# a LIST of lines:
# ['Hello, SpongeBob!\n', 'Welcome to Bikini Bottom.\n']

Which One Should I Use?

  • 📖read() — when you want everything at once.
  • 📖readline() — when you only need one line.
  • 📖readlines() — when you want each line as a list item.
13 / 22

Looping Over a File Line by Line 🔁

with open("notes.txt", "r") as file:
    for line in file:
        print(line.strip())

# Hello, SpongeBob!
# Welcome to Bikini Bottom.

What is Happening?

  • 🔁A file can be looped over directly, one line at a time.
  • 🔁Each line includes a trailing newline character "\n".
  • 🔁.strip() removes that extra newline for clean printing.
📌 This is the most memory-friendly way to process a large file — Python reads one line at a time.

Writing to Files: Mode "w" ✍️

with open("notes.txt", "w") as file:
    file.write("Hello, SpongeBob!\n")
    file.write("Welcome to Bikini Bottom.\n")

# notes.txt now contains exactly those two lines.
# Anything that was in the file before is GONE.

Key Points About "w" Mode

  • ✍️Creates the file if it does not exist yet.
  • ✍️Erases all existing content before writing.
  • ✍️write() does not add a newline automatically — add \n yourself.
⚠️ Opening a file in "w" mode wipes it immediately, even if you never call write() afterward.
15 / 22

Appending to Files: Mode "a" ➕

with open("notes.txt", "a") as file:
    file.write("See you tomorrow!\n")

# notes.txt now contains:
# Hello, SpongeBob!
# Welcome to Bikini Bottom.
# See you tomorrow!

"w" vs "a" — Do Not Mix Them Up!

  • ✍️"w" — overwrites the whole file. Old data is lost.
  • ➕"a" — adds to the end. Old data stays safe.
✅ Use "a" for things like logs or diaries, where you want to keep adding entries over time.
16 / 22

"r+" Mode: Read and Write Together 🔁

# notes.txt already contains:
# Hello, SpongeBob!
# Welcome to Bikini Bottom.

with open("notes.txt", "r+") as file:
    content = file.read()   # read what is already there
    print(content)
    file.write("Patrick was here!\n")  # then write more

with open("notes.txt", "r") as file:
    print(file.read())
# Hello, SpongeBob!
# Welcome to Bikini Bottom.
# Patrick was here!

"r+" — Both Read and Write, No Erasing

  • 🔁Unlike "w", opening with "r+" does not erase the file.
  • 🔁You can call both read() and write() on the same file object.
  • 🔁Writing happens from the current position — after file.read(), that position is the end of the file.
⚠️ Like "r", the file must already exist — "r+" cannot create a new file. Use "w" or "a" for that.
17 / 22

Writing Multiple Lines with writelines() 📝

lines = [
    "Hello, SpongeBob!\n",
    "Welcome to Bikini Bottom.\n",
    "See you tomorrow!\n"
]

with open("notes.txt", "w") as file:
    file.writelines(lines)

write() vs writelines()

  • ✍️write() takes one string.
  • 📝writelines() takes a list of strings.
  • 📝Neither one adds \n for you — put it in each string yourself.
💡 writelines() does not add blank lines between items — that is why each string in the list ends with \n.

Mini Project: A Simple Diary Program 📔

def add_entry(text: str) -> None:
    with open("diary.txt", "a") as file:
        file.write(text + "\n")

def show_diary() -> None:
    with open("diary.txt", "r") as file:
        for line in file:
            print("-", line.strip())
add_entry("Today I learned file handling!")
add_entry("Encapsulation makes my code safer.")

show_diary()
# - Today I learned file handling!
# - Encapsulation makes my code safer.
📔 add_entry() appends, so running the program again keeps every past entry instead of erasing them.

Deleting Files and Folders 🗑️

Delete a File

Import the os module, then call os.remove().

import os

os.remove("demofile.txt")

Check Before You Delete

Avoid an error by checking the file exists first.

import os

if os.path.exists("demofile.txt"):
    os.remove("demofile.txt")
else:
    print("The file does not exist")

Delete a Folder

Use os.rmdir() to remove an entire folder.

import os

os.rmdir("myfolder")

Key Points

  • 🗑️Deleting always needs import os first.
  • 🗑️os.remove() on a missing file raises FileNotFoundError.
  • 🗑️os.path.exists() lets you check safely before deleting.
  • 🗑️os.rmdir() only works on an empty folder.
⚠️ Deleting is permanent — there is no undo and no trash bin. Always double-check the filename first.

Common Mistakes - Don't Fall For These! ⚠️

❌ Thinking __balance is truly private
account.__balance ← AttributeError
account._BankAccount__balance ← still reachable!
# Name mangling is a strong hint, not a lock.
❌ Forgetting the parentheses when calling a method
print(p1.get_age) ← prints a method object!
print(p1.get_age()) ← correct, prints 25
❌ Opening in "w" mode when you meant "a"
open("diary.txt", "w") ← erases old entries!
open("diary.txt", "a") ← adds a new entry safely
❌ Forgetting to close a file
file = open("notes.txt")
... forgot file.close() ...
# Fix: use "with open(...) as file:" instead
❌ Reading a file that does not exist
open("missing.txt", "r") ← FileNotFoundError
# "r" mode needs the file to already exist.
❌ Forgetting "\n" when writing lines
file.write("Hello")
file.write("World")
# Result: "HelloWorld" all on one line!
